Product Requirements Document

AI Meeting Summarizer

A tool that transforms raw meeting transcripts into structured summaries with decisions, action items, owners, and open questions — in seconds.

Author
Nicole Surawski
Version
v1.0
Status
Shipped (MVP)
Target User
B2B SaaS Teams

TL;DR

B2B teams spend hours writing meeting notes, and important decisions and action items still slip through the cracks. The AI Meeting Summarizer lets users paste any meeting transcript and get a structured, shareable summary with decisions, action items (with owners and deadlines), and open questions — all extracted automatically using Claude's language model. A follow-up tracker persists unresolved items across sessions so nothing gets lost.

Problem Statement

In B2B SaaS organizations, meetings are where critical product decisions are made, work is assigned, and cross-functional alignment happens. But the output of most meetings is either:

  • No notes at all — decisions are lost and action items are forgotten
  • Unstructured notes — someone spends 15-30 minutes writing a recap that buries key decisions inside paragraphs of text
  • Inconsistent formats — every note-taker structures things differently, making it hard to scan for what matters
The insight: Meeting transcripts already contain all the information — the problem is extraction and structure, not capture. AI can solve this in seconds instead of the 15-30 minutes a human takes.

Target Users

User Segment Pain Point Primary Benefit
Product Managers Spend significant time writing meeting recaps; need structured decisions and action items for roadmap alignment Instant structured output they can paste into Notion, Slack, or Confluence
Engineering Managers Need clear action items with owners from sprint planning and standups Auto-extracted action items with owner attribution
Customer Success / Account Managers Must track commitments made to clients across many calls Follow-up tracker that persists unresolved items across meetings
Team Leads / ICs Miss context from meetings they didn't attend Scannable TL;DR and topic breakdown for async catch-up

User Stories

  1. As a PM, I want to paste a meeting transcript and get a structured summary so that I can share decisions and action items with my team within minutes of a meeting ending.
  2. As an engineering lead, I want action items auto-extracted with owners and deadlines so that I can track sprint commitments without manual note-taking.
  3. As someone who missed a meeting, I want a TL;DR and topic breakdown so that I can catch up in 30 seconds instead of reading a full transcript.
  4. As a CSM managing multiple accounts, I want unresolved questions and action items to persist across meetings so that client commitments don't fall through the cracks.
  5. As any user, I want to copy the entire summary in a clean format so that I can paste it directly into Slack, email, or a project management tool.

Functional Requirements

P0 — Must Have (v1)

ID Requirement Acceptance Criteria
FR-01 Transcript input via text area User can paste any free-form text transcript; word count displays in real-time; clear button resets input
FR-02 AI-generated structured summary Returns JSON with: title, TL;DR, topics discussed, decisions (with context), action items (with owner + due date), and open questions
FR-03 Owner inference AI infers task owners from conversational context (e.g., "I'll handle that" → speaker is owner); marks ambiguous owners as "TBD"
FR-04 Copy all summary as markdown One-click copies the full summary as formatted markdown; visual confirmation shown on copy
FR-05 Sample transcript "Load sample" button populates a realistic B2B meeting transcript for first-time users to try the tool without providing their own data
FR-06 Follow-up tracker Action items and open questions persist to localStorage across sessions; items can be marked resolved; grouped by meeting title
FR-07 Error handling Clear error messages for: missing API key, API failures, malformed responses; errors are dismissible

P1 — Should Have (v2)

  • File upload support (drag-and-drop .txt, .vtt, .srt transcript files)
  • Meeting history with search — browse and re-open past summaries
  • Export to PDF or Google Docs format
  • Team sharing — generate a shareable link for a summary

P2 — Nice to Have (Future)

  • Direct integration with Zoom/Google Meet/Teams for auto-capture
  • Slack bot that summarizes meeting channels on command
  • Recurring meeting comparison (diff summaries across weekly standups)
  • Custom summary templates (e.g., sprint review vs. client call vs. 1:1)

Output Schema

The AI returns a structured JSON object with the following fields:

Field Type Description
title string Inferred meeting title or topic
tldr string 2-3 sentence executive summary
topics[] array Each topic discussed, with title and brief summary
decisions[] array What was decided + rationale/context
actionItems[] array Task, owner (inferred or "TBD"), and due date (inferred or "TBD")
openQuestions[] array Unresolved questions or parking lot items

Non-Functional Requirements

  • Performance: Summary generation should complete within 5-10 seconds for a typical 30-minute meeting transcript
  • Data privacy: No transcripts are stored server-side; all persistence is client-side via localStorage
  • Accessibility: Keyboard-navigable; sufficient color contrast ratios; loading states are announced
  • Responsive: Fully functional on mobile and tablet viewports
  • Zero build step: v1 runs as a single React app with no backend infrastructure required

Out of Scope (v1)

Explicitly excluded to keep v1 focused and shippable:
  • Real-time meeting transcription (audio → text) — users provide existing transcripts
  • Multi-language support — v1 is English-only
  • User authentication or accounts — the tool is sessionless
  • Calendar integration — no connection to Google Calendar, Outlook, etc.
  • Collaborative editing of summaries — output is read-only (copy to edit elsewhere)
  • Custom AI model selection — v1 uses Claude Sonnet exclusively

Success Metrics

Metric Target Rationale
Summary accuracy (decisions + action items correctly extracted) ≥ 90% Users will abandon the tool if they have to manually fix most of the output
Time from paste to summary < 10 seconds Must be faster than manual note-taking to justify the workflow switch
Copy-to-clipboard usage rate ≥ 70% of summaries Indicates the output is useful enough to share with the team
Repeat usage (2+ meetings summarized) ≥ 60% of users First session is curiosity; second session is adoption
Follow-up tracker engagement (items marked resolved) ≥ 40% of tracked items Validates that the tracker drives real follow-through, not just data capture

Technical Architecture (v1)

  • Frontend: React 18 (Vite build), single-page application
  • AI Layer: Claude API (claude-sonnet model) via direct browser fetch with structured JSON system prompt
  • Persistence: localStorage for follow-up tracker and meeting history
  • Auth: User-provided API key (stored in session memory only, not persisted)
  • Hosting: Static deployment — no backend server required
Architecture decision: Direct browser-to-API approach was chosen for v1 to eliminate backend complexity and ship faster. For a production version, a thin backend proxy would handle API key management and add rate limiting.

Assumptions & Risks

Assumptions

  • Users have access to text transcripts from their meeting tools (Zoom, Google Meet, Teams, Otter.ai, etc.)
  • Most B2B meetings have identifiable speakers, decisions, and action items in the transcript
  • Claude's structured output capabilities are reliable enough for production-quality extraction

Risks

Risk Likelihood Impact Mitigation
AI hallucinates action items or owners not in the transcript Medium High System prompt explicitly instructs "TBD" for ambiguous cases; users can visually verify against source
Very long transcripts exceed token limits Medium Medium v1 max_tokens is set to 1000; v2 would chunk long transcripts or use a higher-context model
Sensitive meeting content sent to external API Low High Clear disclosure in UI; v2 could offer on-premise deployment or SOC 2 compliant API endpoints

Open Questions

  1. Should v2 support custom summary templates (sprint review vs. client call vs. all-hands), or is the current universal format sufficient?
  2. What's the right persistence model for teams? localStorage works for individual use, but teams need shared access to summaries.
  3. Should the follow-up tracker integrate with task management tools (Jira, Linear, Asana) or stay lightweight?
  4. Is there demand for sentiment analysis (e.g., flagging contentious topics or disagreements)?
