Product Requirements Document

To-Do Prioritizer

A task prioritization tool that scores to-dos by urgency, importance, and effort — then auto-ranks them so users always know what to tackle first.

Author
Nicole Surawski
Version
v1.0
Status
Shipped (MVP)
Target User
Individual Contributors & Managers

TL;DR

Most to-do apps help you list tasks but not decide what to work on first. The To-Do Prioritizer introduces a weighted scoring model that evaluates every task across three dimensions — urgency, importance, and effort — and automatically categorizes them into High, Medium, and Low priority. Users can adjust the scoring weights to match their current work context (deep work, fire drill, quick wins), and the tool provides transparent reasoning for every ranking decision.

Problem Statement

People don't struggle with knowing what they need to do — they struggle with knowing what to do first. Existing to-do apps treat all tasks as equal, leaving users to constantly re-evaluate priorities in their heads. This leads to:

  • Decision fatigue — spending mental energy deciding what to work on instead of doing the work
  • Urgency bias — defaulting to whatever feels most pressing, even when a high-impact task should take priority
  • Effort avoidance — skipping important-but-hard tasks in favor of easy wins that don't move the needle
  • No framework for changing contexts — what matters on a deadline day is different from a deep work day, but most tools don't adapt
The insight: Prioritization isn't subjective — it's a function of urgency, importance, and effort with context-dependent weights. Making this scoring model explicit and adjustable gives users a principled way to decide what to do next.

Target Users

User Segment Pain Point Primary Benefit
Individual Contributors Long to-do lists with no clear order; spend time deciding instead of doing Instant ranked priorities with transparent reasoning
Managers / Team Leads Need to balance team requests, deadlines, and strategic work across competing demands Adjustable weight presets for different work contexts (sprint planning vs. fire drill)
Students / Career Transitioners Juggling personal, professional, and learning tasks with no systematic approach Low-friction tool that teaches prioritization thinking through scoring transparency

User Stories

  1. As a user with 20+ tasks, I want each task scored and ranked automatically so that I can stop spending mental energy deciding what to do next.
  2. As a user facing a deadline crunch, I want to switch to a "Deadline-driven" weight preset so that urgency-based tasks float to the top.
  3. As a user doing deep work, I want to switch to an "Impact-first" preset so that the highest-value tasks surface regardless of deadlines.
  4. As a user, I want to see why each task ranked where it did so that I can trust and learn from the prioritization.
  5. As a user, I want to break tasks into subtasks with their own progress tracking so that large projects feel manageable.
  6. As a user, I want to drag and manually reorder tasks when my judgment overrides the algorithm.
  7. As a user who completes all tasks, I want a celebration moment so that finishing feels rewarding.

Scoring Model

The prioritization engine uses a weighted linear scoring model with three input dimensions:

score = (urgency × w1) + (importance × w2) + ((6 - effort) × w3)

// Urgency is derived from due date:
Today or overdue → 5  |  Within 3 days → 4  |  Within 7 days → 3  |  Within 30 days → 2  |  No deadline → 1

// Importance and Effort are user-rated 1–5
// Effort is inverted (6 - effort) so lower effort = higher score

// Priority labels:
Score 3.5–5.0 = HIGH  |  2.0–3.4 = MEDIUM  |  0.0–1.9 = LOW

Weight Presets

Preset Urgency Importance Effort Best For
Balanced 40% 40% 20% Default — general daily planning
Deadline-driven 60% 30% 10% Sprint deadlines, end-of-quarter crunch
Impact-first 20% 70% 10% Strategic deep work days, planning sessions
Quick wins 20% 30% 50% Low-energy days, clearing the backlog
Design decision: Weights are user-adjustable via sliders (range 10–80%) and always constrained to sum to 100%. When one slider moves, the other two adjust proportionally. This prevents invalid states while giving users full control.

Functional Requirements

P0 — Must Have (v1)

ID Requirement Acceptance Criteria
FR-01 Add tasks via text input User types a task name and presses Enter or clicks Add; task appears in "Unprioritized" section
FR-02 Score tasks across three dimensions Scoring panel lets user set due date (calendar picker), importance (1–5 dot selector), and effort (1–5 dot selector); live score preview updates as inputs change
FR-03 Auto-categorize by priority Scored tasks auto-sort into High (3.5–5.0), Medium (2.0–3.4), and Low (0.0–1.9) sections with color-coded badges
FR-04 Adjustable weight sliders Three sliders for urgency, importance, and effort; always sum to 100%; moving one slider proportionally adjusts the others
FR-05 Weight presets Four presets (Balanced, Deadline-driven, Impact-first, Quick wins) that instantly apply predefined weight configurations
FR-06 Priority reasoning Each scored task displays a short explanation (e.g., "Due soon dominates priority" or "High impact + Quick win")
FR-07 Task completion Checkbox marks task as complete; completed tasks move to a collapsible "Completed" section; tasks can be restored
FR-08 Task deletion with confirmation Delete button shows inline confirmation ("Delete this task?") with Keep/Delete options to prevent accidental data loss
FR-09 Subtasks Each task supports nested subtasks with their own completion tracking; subtask progress bar shows fraction completed
FR-10 Drag-and-drop reorder Users can manually reorder tasks within or across sections by dragging
FR-11 Progress tracking Global progress bar and counter (X/Y done) visible at all times
FR-12 Celebration on completion Confetti animation and congratulatory overlay when all tasks are marked complete
FR-13 Data persistence All tasks, weights, and preset selection persist to localStorage and survive page refreshes

P1 — Should Have (v2)

  • AI-powered task suggestions ("Based on your list, consider breaking X into subtasks")
  • Recurring tasks with configurable frequency (daily, weekly, monthly)
  • Due date notifications / browser reminders
  • Tags and filtering (e.g., "Work", "Personal", "Health")
  • Keyboard shortcuts for power users (J/K to navigate, X to complete, P to prioritize)

P2 — Nice to Have (Future)

  • Calendar view showing tasks plotted against deadlines
  • Team mode — shared task boards with role-based weights
  • Analytics dashboard (completion rate trends, priority distribution over time)
  • Integration with calendar apps for auto-generated urgency from scheduled deadlines
  • Natural language task input ("Call dentist by Friday, high importance")

Key UX Design Decisions

Decision Rationale Alternative Considered
Dot selectors (1–5) instead of dropdowns for importance/effort Faster interaction, visual weight makes the rating feel tangible, works well on mobile Numeric dropdowns — rejected as slower and less engaging
Live score preview in the scoring panel Users see the impact of their inputs before saving, building trust in the scoring model Score only shown after save — rejected because it makes the model feel like a black box
Inline delete confirmation instead of modal Less disruptive flow; user stays in context rather than losing focus to a modal dialog Browser confirm() dialog — rejected as jarring and non-brandable
Weight sliders always sum to 100% Prevents invalid weight states; intuitive "give more to X, take from Y" mental model Independent sliders normalized at calculation time — rejected as confusing UX
Confetti celebration on completion Emotional payoff that reinforces the habit loop; makes the tool feel human and rewarding Simple checkmark animation — rejected as forgettable

Non-Functional Requirements

  • Performance: All scoring calculations run client-side with zero network latency; UI updates within 16ms (60fps animations)
  • Data privacy: All data stays in the browser via localStorage; no server, no tracking, no analytics
  • Accessibility: Keyboard-navigable; color-coded priorities also use text labels (not color alone); sufficient contrast ratios
  • Responsive: Fully functional on mobile viewports; touch-friendly interaction targets (≥44px)
  • Zero build step: Runs via CDN-loaded React and Tailwind — open the HTML file and it works

Out of Scope (v1)

Explicitly excluded to ship a focused MVP:
  • User accounts or authentication — the tool is single-user and sessionless
  • Backend server or database — all data lives in localStorage
  • AI-generated prioritization suggestions — v1 uses a deterministic scoring model
  • Collaboration features — no shared lists or team views
  • Import/export (CSV, JSON) — data lives in the browser only
  • Calendar or notification integrations

Success Metrics

Metric Target Rationale
% of tasks that get scored (not left in "Unprioritized") ≥ 75% If users aren't scoring tasks, the core value prop isn't landing
Task completion rate ≥ 60% The tool should drive follow-through, not just list-making
Preset usage (users try at least 2 presets) ≥ 40% Validates that context-aware weighting is a real user need, not a feature for its own sake
Return usage (3+ sessions) ≥ 50% Indicates the tool earns a place in the user's workflow
Subtask adoption rate ≥ 30% Validates that users need task decomposition, informing v2 scope

Technical Architecture (v1)

  • Frontend: React 18 (CDN) + Tailwind CSS (CDN) + Babel (in-browser transpilation)
  • State management: React useState + useCallback with localStorage sync
  • Scoring engine: Pure client-side calculation — deterministic, no API calls
  • Persistence: localStorage with JSON serialization for tasks, weights, and active preset
  • Drag-and-drop: Native HTML5 drag events (no library dependency)
  • Hosting: Static file — works from local filesystem or any static host
Architecture decision: CDN-loaded React with in-browser Babel was chosen for v1 to eliminate all build tooling. This trades a small performance cost (Babel compilation on load) for maximum deployment simplicity. A production version would move to Vite with proper bundling.

Assumptions & Risks

Assumptions

  • Users want a lightweight tool, not a full project management platform
  • A three-factor scoring model (urgency, importance, effort) captures enough signal for personal task prioritization
  • Users will invest 10–15 seconds per task to score it if the payoff is clear and immediate
  • localStorage is sufficient for single-user, single-device persistence in v1

Risks

Risk Likelihood Impact Mitigation
Scoring friction causes users to skip prioritization Medium High Live preview makes scoring feel fast and transparent; dot selectors minimize input time to ~5 seconds per task
Three factors are too simplistic for complex work Low Medium Drag-and-drop override lets users manually adjust when the algorithm doesn't match their judgment
localStorage data loss (browser clear, device switch) Medium Medium v2 adds cloud sync or export/import; v1 accepts this as a known limitation
Users don't discover weight presets Medium Low Weights panel shows current configuration inline; presets are prominently displayed when panel is open

Open Questions

  1. Should v2 allow users to create custom presets, or are the four built-in presets sufficient for most use cases?
  2. Is there demand for a "focus mode" that shows only the top 3 tasks and hides everything else?
  3. Should completed tasks be auto-archived after a configurable time period, or kept indefinitely?
  4. Would users benefit from a weekly email digest showing their completion rate and priority distribution?
  5. Is there a market for team-shared priority boards where a manager sets the weight configuration for the whole team?
